# 璃音 Lucent 商用平台設計規格

日期：2026-08-23  
狀態：待使用者審閱  
範圍：在現有 Electron／React 專案上擴充，不重做專案、不改換框架

## 1. 目標

將璃音 Lucent 從單機歌詞藥丸擴充為可商用維護的桌面產品，具備：

- 應用程式內的網易雲音樂播放能力。
- 本機網易雲、內建播放器與房間主持人之間明確且唯一的播放來源優先級。
- 使用者自己的網易雲帳號、網易雲歌單及僅存在璃音本機的自訂歌單。
- 房間點歌佇列、主持人權限與可靠的狀態同步。
- 可簽署、可分階段發布、可回復的自動更新機制。
- 舊設定無痛遷移，並移除字幕提前／延遲及藥丸 RGB 外框。

本設計保留現有液態玻璃藥丸、網易雲桌面端偵測、鏡像歌詞、逐字歌詞、局域網房間、外觀配置與粒子過場。商用改造不得降低既有歌詞同步與動畫表現。

## 2. 已確認的產品規則

### 2.1 播放來源優先級

單機模式：

1. 本機網易雲桌面端正在播放。
2. 璃音內建播放器正在播放。
3. 無有效來源時顯示待機狀態。

房間主持人：

1. 主持人本機網易雲桌面端正在播放。
2. 主持人璃音內建播放器正在播放。
3. 無有效來源時房間進入等待狀態。

房間成員：

1. 房間主持人的權威播放狀態永遠優先。
2. 成員本機網易雲與成員內建播放器不得改寫藥丸內容。
3. 離開房間後立即恢復單機模式的來源優先級。

主持人授權成員控制播放時，成員只送出控制命令；播放來源及房間權威狀態仍由主持人端產生，成員不會變成新的狀態來源。

### 2.2 本階段的房間音訊範圍

第一個商用里程碑同步歌名、歌手、封面、歌詞、進度、播放狀態、點歌佇列及藥丸視覺參數。實際音訊只在主持人端播放，不把主持人的 Cookie、歌曲播放網址或音訊串流轉發給房間成員。

這項限制可避免帳號憑證外洩、播放網址濫用、跨裝置授權不明及局域網音訊同步造成的延遲與維護成本。

### 2.3 換歌粒子過場

既有「原位粒子破碎」需求保留：

- 音樂真正結束或確定切歌時，藥丸內容在原位逐步粒子化並慢慢飄散。
- 破碎期間停止滑鼠傾斜、流光、唱片旋轉與其他互相衝突的動畫。
- 粒子狀態持續保留，不閃回完整舊藥丸。
- 新歌的歌曲資料、唱片頭像與專輯封面都準備完成後才開始重組。
- 重組使用同一批粒子反向聚合，不直接換成完整新藥丸。
- 每次破碎的起點、區域與粒子路徑可隨機，但隨機只用於視覺過場，不冒充音訊節拍或歌詞時間。

## 3. 商用邊界與非目標

本階段不包含：

- 房間成員端同步播放音訊。
- 網際網路房間服務；現有房間維持局域網範圍。
- 音樂下載、離線快取、破解 VIP、DRM 規避或區域限制規避。
- 用隨機值偽裝音量、節拍、PCM 或 FFT 分析。
- 遊戲 HUD、遊戲模式、遊戲偵測、FPS／MOBA 功能或遊戲專用配置。
- 讓成員以本機播放器覆蓋主持人狀態。

## 4. 法務與供應商策略

目前使用的 NeteaseCloudMusicApi 類套件屬非官方接口封裝。其程式碼授權不等於取得網易雲服務、音樂內容、帳號登入或商業播放的授權。

商用版本採用可替換的 `MusicProvider` 邊界：

- 正式發行：接入經書面授權的網易雲接口或合法內容供應商。
- 開發與內部驗證：既有非官方 NetEase Provider 僅能受開發旗標控制，不進入正式商售建置。
- 伴隨模式：本機網易雲桌面端偵測可繼續作為使用者已安裝官方客戶端時的整合來源，但仍需在隱私政策與使用條款中清楚揭露。

未取得正式授權前，不宣稱內建網易雲串流已符合商業發行條件，也不把非官方 API 當作不可替換的核心架構。

## 5. 核心架構

### 5.1 PlaybackCoordinator

新增單一播放仲裁器 `PlaybackCoordinator`。所有藥丸、歌詞、封面、房間廣播及進度條只訂閱仲裁器輸出的權威快照，不直接各自讀取 SMTC、CDP、內建播放器或房間訊息。

標準快照 `PlaybackSnapshot` 包含：

- `source`：`desktop-netease`、`internal-player`、`room-host` 或 `idle`。
- `trackId`、`title`、`artist`、`album`、`durationMs`。
- `coverUrl`、`artistAvatarUrl`。
- `positionMs`、`playing`、`capturedAt`。
- `songRevision`：切歌時遞增，阻止舊請求覆蓋新歌。
- `lyrics`、`mirror` 及其來源標記。
- `assetsReady`：歌曲資料、封面與唱片素材是否已完成載入。

仲裁器只允許一個來源成為 active source。來源切換會產生新 revision，Renderer 必須以 revision 丟棄過期歌詞、封面及動畫回呼。

### 5.2 來源介面

三個來源 Adapter 共用相同介面：

- `DesktopNeteaseSource`：包裝現有 CDP、SMTC 與視窗偵測。
- `InternalNeteasePlayerSource`：包裝璃音內建播放器。
- `RoomHostSource`：房間成員接收主持人權威快照。

每個 Adapter 只負責輸出狀態，不直接寫 UI。來源是否有效由 `playing`、最近更新時間、歌曲身分及連線健康狀態共同判斷。

### 5.3 接管行為

- 內建播放器播放時，如果本機網易雲桌面端開始播放，璃音暫停內建播放器並切到桌面端。
- 桌面端停止後不自動恢復內建播放器，避免突然雙重播放；使用者需主動按播放。
- 房間成員加入後，保存但不顯示本機來源狀態；離房時重新仲裁本機來源。
- 主持人來源切換只算同一首歌的來源切換或一次實際切歌，不重播兩次換歌動畫。

## 6. 內建播放器

### 6.1 播放所有權

新增專用且不可見的音訊服務 Renderer，內含唯一 `<audio>` 元素。設定視窗關閉不會停止音樂，Overlay 也不承擔播放責任。

主程序透過 IPC 向音訊服務傳送：

- 載入歌曲。
- 播放、暫停、上一首、下一首。
- 跳轉進度及音量。
- 佇列替換與佇列項目操作。

音訊服務回報原生 media events，`PlaybackCoordinator` 由這些事件更新快照。不得建立另一個獨立高頻進度計時器。

### 6.2 歌曲 URL 與失敗處理

- Provider 回傳的短效播放 URL 不寫入設定、不分享至房間、不記錄於日誌。
- URL 過期或 401／403 時只重取一次；仍失敗則標記歌曲不可播放並通知主持人。
- 不下載音樂、不建立永久媒體快取。
- 無權限、VIP、區域限制與下架歌曲顯示明確原因，不嘗試繞過。

## 7. 帳號與憑證安全

- 每位使用者登入自己的網易雲帳號。
- 登入憑證使用 Electron `safeStorage` 加密後保存，不再以明文 Cookie 檔保存。
- Cookie、播放 URL、設備識別資訊不得寫入一般日誌、房間封包或外觀配置。
- 登出會撤銷本機憑證、清除記憶體中的 session 並停止需要帳號的請求。
- 啟動時檢查登入有效性；過期時回到登入狀態，不進入無限重試。
- 移除固定 `REAL_IP`；正式 Provider 由服務端或授權規格決定必要網路參數。
- 應用內提供隱私說明、資料用途、保存位置及刪除帳號資料入口。

## 8. 歌單與本機資料

### 8.1 網易雲歌單

- 登入後可讀取使用者有權存取的網易雲歌單與歌曲。
- 網易雲歌單在璃音中先以唯讀方式呈現，避免誤修改雲端資料。
- 播放時仍由 Provider 逐首驗證可用性。

### 8.2 璃音本機歌單

本機歌單不回寫網易雲。使用 SQLite 保存，避免把佇列與大量歌曲塞入設定 JSON。

資料表：

- `local_playlists(id, name, created_at, updated_at)`。
- `local_playlist_items(id, playlist_id, provider, track_id, position, added_at)`。
- `room_queue_entries(id, room_id, provider, track_id, requester_id, status, position, created_at, updated_at)`。
- `db_migrations(version, applied_at)`。

刪除本機歌單只刪除璃音資料，不影響網易雲帳號與歌單。

## 9. 房間、點歌與權限

### 9.1 權威模型

主持人是房間播放狀態的唯一權威。所有命令都帶有 `roomRevision`、`commandId` 與發送者身分；主持人確認後才改變房間狀態。

角色與能力：

- 主持人：完整播放、佇列與授權權限。
- 一般成員：可瀏覽、同步藥丸及提交點歌。
- 獲授權成員：依主持人授予的能力執行控制。

細分能力：

- `song.request`：提交點歌。
- `queue.manage`：調整、移除與核准佇列項目。
- `playback.control`：播放、暫停、切歌與跳轉。

授權可隨時撤銷，撤銷後的新命令立即拒絕；已核准的佇列項目不會因此消失。

### 9.2 點歌流程

1. 成員提交 provider 與 track ID。
2. 主持人驗證歌曲詳情、可播放性及重複狀態。
3. 合法請求加入待播放佇列並廣播結果。
4. 未授權成員不能直接播放，只能等待主持人或佇列規則執行。
5. 每位成員設置請求頻率與未處理數量上限，避免洗佇列。

### 9.3 斷線與重連

- 主持人廣播單調遞增的 `roomRevision`。
- 成員重連後先取得完整 snapshot，再接續增量事件。
- 重複 `commandId` 只執行一次。
- 主持人斷線時成員凍結最後狀態並顯示「等待主持人」，不把本機播放器提升為房間來源。
- 房間封包不包含 Cookie、音訊 URL 或可重用登入憑證。

## 10. 自動更新與發佈

正式版本使用簽署的 NSIS 安裝程式與 `electron-updater`：

- HTTPS 更新來源包含安裝包、差分檔、版本清單與校驗資訊。
- 支援穩定版與測試版頻道，使用者可選擇是否接收測試版。
- 啟動後延遲檢查，也可由設定頁手動檢查。
- 下載顯示版本、大小與進度；安裝前展示更新說明。
- 正在播放或主持房間時不強制重啟，等待使用者確認。
- 發佈採分階段比例並保留上一個可回復版本。
- Windows 安裝包與更新檔必須使用程式碼簽章。
- Portable 版本保留，但只支援手動下載更新，不宣稱具備可靠的自動更新能力。

更新器不得在開發模式執行，也不得把未簽署測試包推送到穩定頻道。

## 11. 設定移除與相容性

Config Schema 升級一版：

- 刪除 UI 中的字幕提前／延遲控制。
- Renderer 不再讀取 `offset`，歌詞位置只由權威播放時間及鏡像高亮決定。
- 刪除藥丸 `borderRGB` 的 UI、渲染 class、預設值、隨機外觀及外觀配置快照欄位。
- 進度條 RGB、其他使用者保留的色彩效果不受影響。
- 舊設定中的 `offset` 與 `borderRGB` 可被遷移器讀取但忽略，不造成啟動失敗。
- 舊命名外觀配置載入時過濾淘汰欄位，其餘玻璃與外觀參數保持不變。
- 未知欄位採安全 merge，不要求使用者刪除設定檔。

SQLite 使用獨立 schema version；資料庫遷移與 Config 遷移不可互相綁死。

## 12. UI 資訊架構

設定視窗維持繁體中文與現有液態玻璃風格，新增或整理為：

- 帳號：登入狀態、重新登入、登出、隱私與本機資料刪除。
- 播放器：目前來源、播放控制、音量、佇列與來源接管提示。
- 歌單：網易雲歌單與璃音本機歌單分區顯示。
- 房間：成員、點歌佇列、能力授權及連線狀態。
- 更新：目前版本、頻道、檢查更新、下載進度與更新說明。

來源切換時顯示簡短提示，例如「已切換至電腦上的網易雲音樂」，但不反覆彈窗。房間成員查看本機播放控制時需清楚顯示「目前跟隨房主」。

## 13. 效能與動畫隔離

- 播放進度沿用單一時鐘與媒體事件校準，不為內建播放器新增第二套歌詞計時器。
- 房間播放 tick 使用現有低頻同步及本地插值，不逐幀傳送。
- `PlaybackSnapshot` 以變更事件發布，避免整個 UI 每幀重算。
- 專輯封面與頭像解碼完成後才將 `assetsReady` 設為 true。
- 粒子破碎使用固定上限與可重用粒子池；飄散後保持粒子狀態，不持續生成。
- 破碎時停用其他藥丸動畫；重組完成後才恢復。
- 控制台關閉後停止其預覽動畫，音訊服務仍可獨立運作。

## 14. 錯誤狀態

- 桌面網易雲偵測失效：若不在房間且內建播放器已由使用者主動播放，維持內建來源；否則進入待機。
- 帳號過期：停止需要授權的新請求，提示重新登入，不清除本機歌單。
- 歌曲不可播放：跳過該佇列項目並記錄對使用者可讀的原因。
- 封面或頭像失敗：使用璃音內建占位素材；粒子重組不能無限等待，逾時後以占位素材完成。
- 房間斷線：成員顯示等待主持人，不接管房間藥丸。
- 更新失敗：保留現有版本可正常啟動，顯示可重試的錯誤，不刪除舊安裝。

## 15. 實作階段

### 階段 0：商用前置條件

- 確認網易雲或內容供應商的書面授權路徑。
- 決定更新伺服器、簽章憑證、隱私政策及服務條款。
- 建立正式 Provider 與開發 Provider 的建置隔離。

### 階段 1：設定清理與播放仲裁

- 移除字幕 offset 與藥丸 RGB 外框。
- 新增 Config migration。
- 建立 `PlaybackCoordinator`、標準快照與來源優先級單元測試。
- 將現有 Desktop NetEase 與 Room 狀態接到仲裁器。

### 階段 2：內建音訊服務

- 新增獨立音訊服務 Renderer。
- 完成播放控制、進度事件、URL 更新與錯誤狀態。
- 驗證桌面網易雲接管、停止後不自動恢復及房間成員鎖定。

### 階段 3：帳號、歌單與本機資料

- 明文 Cookie 遷移到 `safeStorage`。
- 移除固定 `REAL_IP`。
- 完成網易雲歌單讀取、本機 SQLite 歌單與資料遷移。

### 階段 4：房間點歌與權限

- 擴充協議版本、佇列、能力授權、命令去重與重連 snapshot。
- 加入請求限流、不可播放歌曲處理與主持人 UI。

### 階段 5：自動更新與發佈管線

- 加入 NSIS、`electron-updater`、簽章、頻道及分階段發佈。
- 完成兩個實際封裝版本間的升級與回復驗證。

### 階段 6：回歸與商用封裝

- 回歸網易雲桌面偵測、歌詞鏡像、逐字高亮、封面、唱片、粒子過場、房間及外觀配置。
- 完成長時間播放、快速切歌、休眠恢復、網路斷線與多螢幕測試。
- 所有任務完成後才統一產出商用 EXE，不在每個小批次重複封裝。

## 16. 驗收標準

1. 單機時，桌面網易雲播放可在一次狀態更新內接管內建播放器的藥丸。
2. 接管時內建播放器暫停，不產生雙重音訊。
3. 房間成員的本機播放器永遠不能覆蓋主持人藥丸。
4. 離開房間後來源仲裁恢復正常。
5. 主持人可授予及撤銷 `queue.manage` 與 `playback.control`。
6. 未授權成員只能提交點歌，不能直接播放、切歌或跳轉。
7. 快速 A → B → C 切歌時只有 C 的資料可提交。
8. 新歌封面與頭像準備完成前保持粒子狀態，完成後慢慢重組且不閃回舊藥丸。
9. 內建播放器關閉設定視窗後仍繼續播放。
10. 網易雲帳號憑證不以明文落盤，也不進入房間封包及日誌。
11. 網易雲歌單可讀取，本機歌單可建立、排序及刪除且不回寫網易雲。
12. 字幕提前／延遲及藥丸 RGB 外框在 UI 與實際渲染中完全移除。
13. 舊 Config 與外觀配置可直接載入，不要求刪檔。
14. 自動更新能從已安裝舊版升級至新版，播放或主持中不強制重啟。
15. 更新失敗後舊版本仍可啟動。
16. 不新增任何遊戲功能，不使用假音訊分析。

## 17. 測試策略

- 單元測試：來源優先矩陣、同曲來源切換、revision、Config migration、權限判斷與命令去重。
- 整合測試：音訊服務事件、短效 URL 更新、safeStorage、SQLite migration、歌單與點歌佇列。
- 房間測試：主持人／成員、授權／撤銷、重連、重複命令、主持人斷線與 snapshot 恢復。
- 實機測試：桌面網易雲播放接管、鏡像歌詞、暫停、拖動、快速切歌、封面載入及粒子重組。
- 更新測試：兩個已簽署測試版本間的下載、驗證、延後安裝、升級與失敗回復。
- 效能測試：閒置、長時間播放、控制台關閉及粒子保持狀態下的 CPU、GPU、記憶體與 DOM／粒子數量。
