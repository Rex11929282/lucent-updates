# 璃音 Lucent：結尾粒子破碎與近距離滑鼠感應設計

## 目標

把目前卡頓的換歌破碎改為真正的「歌曲結束 → 原位粒子散開 → 等待下一首 → 原位粒子重組」。藥丸視窗、螢幕位置與尺寸不移動。另將液態玻璃的滑鼠感應範圍改為可調，預設只在接近藥丸時才觸發。

## 已確認問題

目前 `SongTransitionLayer` 會把完整藥丸 DOM 複製 16 次，再以 CSS 裁切成碎片。每個複本都包含液態玻璃、封面、文字與特效，因此樣式與合成成本很高。它也直接以歌曲 key 改變作為觸發條件，造成手動切歌、播放清單無空窗切歌都會誤破碎。

第三方 `liquid-glass-react` 的內部感應區固定為藥丸外 200px；目前應用把整個 Overlay 容器傳給 `mouseContainer`，所以滑鼠距離藥丸很遠時仍會帶動液態效果。

## 採用方案

### 1. 結尾生命週期

主程序新增只讀的歌曲生命週期事件，Renderer 與局域網成員都接收相同事件：

1. `idle`：正常顯示與播放。
2. `ended`：只有上一首已接近已知時長尾端，且播放器確實停止或下一首的權威歌曲 ID 已抵達時才發出一次。
3. `shatter-out`：保留上一首的靜態畫面，粒子從原位散開並淡出。
4. `dormant`：沒有下一首可播放時維持空白／停止的藥丸，不保留上一句歌詞。
5. `shatter-in`：下一首歌曲 ID、歌詞載入狀態與播放起始條件都已就緒後，以新畫面粒子重組。
6. 回到 `idle`。

手動切歌、拖曳進度或非尾端的歌曲 ID 變更不觸發破碎。若播放清單零空窗自動跳下一首，只有舊歌位置已在時長尾端時才視為正常結束；否則保持正常切歌，避免錯誤遮住新歌。

自然結束的判斷由主程序持有：已知 `durationMs`、估算位置進入尾端容差、播放狀態或權威 CDP 歌曲 ID 的變化三者合併判斷。沒有可靠時長的歌曲寧可不播放破碎，也不猜測結束。

### 2. 單快照 Canvas 粒子層

破碎模式不再複製完整 DOM。結束與重組各只擷取一次藥丸可視表面，交給一個 Canvas 畫面作為來源；有限數量的裁切碎片從同一張圖繪製。這避免 16 個 LiquidGlass、封面與歌詞節點同時重繪。

每個結尾事件只產生一次粒子版圖：

- 依藥丸目前尺寸建立約 12–22 個碎片，上限固定。
- 使用一次性的亂數種子產生不規則中心、三角／多邊形裁切和移動方向；不在每一幀重新亂數，也不模擬音訊資料。
- 粒子散開時向藥丸邊緣分散、淡化、微量旋轉；重組時反向回到新歌畫面。
- Canvas 位於既有視覺裁切層內，套用相同圓角並裁切，因此不會露出矩形、跑到視窗外或改變 BrowserWindow bounds。

畫面來源以 Electron 原生 `webContents.capturePage` 擷取成合成後像素，避免跨來源封面圖片無法被 DOM Canvas 匯出的限制。擷取只發生在過場邊界，不是每幀執行。

### 3. 破碎期間暫停其餘動畫

`shatter-out` 與 `dormant` 期間會啟用 `effectsPaused`：

- 停止裝飾 Canvas、玻璃流光、唱片旋轉與彈跳、進度條流動、文字高亮流動、暫停呼吸與滑鼠液態反應。
- CSS 動畫以統一狀態暫停，而不是個別覆寫 `transform` 或 `filter`。
- 只有粒子 Canvas 自己的單一 `requestAnimationFrame` 可以運行；完成後立即取消。

`shatter-in` 開始時仍保持其他效果停止，直到新畫面完整重組；回到 `idle` 才恢復正常動畫。這可避免背景、進度條與粒子同時重繪造成閃爍。

### 4. 滑鼠感應距離

新增外觀設定 `滑鼠感應距離`，範圍為 0–80px，預設 14px：

- 0px：必須進入藥丸實際邊界才觸發。
- 14px：滑鼠快碰到藥丸時才開始有液態反應。
- 80px：較寬的靠近感應。

Renderer 以藥丸實際矩形計算游標到邊界的最短距離。只有落在設定範圍內時才把真實游標座標提供給 `liquid-glass-react`；範圍外提供中性座標，因此不需要修改 `node_modules` 內硬編碼的 200px 邏輯。相同的近距離狀態也會控制既有 3D 傾斜。此設定不改變拖曳、滑鼠穿透、鎖定、視窗大小或螢幕邊界。

## 設定與相容性

- Config Schema 由 9 升至 10。
- 新增 `cfg.hoverActivationDistance`，安全遷移：缺少時使用 14，讀到非法值時夾在 0–80。
- 既有 `songTransitionMode: 'shatter'` 直接使用新的粒子過場；`none` 與 `collapse` 的既有行為不變。
- 不新增遊戲模式、遊戲偵測、HUD 或音訊假分析。

## 測試與驗收

1. 測試非尾端手動切歌不產生 `ended`，尾端停止只發出一次 `ended`，新歌就緒後才開始 `shatter-in`。
2. 測試 `effectsPaused` 在散開、等待、重組三段均為真，回到 `idle` 才恢復。
3. 測試每次產生的粒子版圖不同、數量有上限、碎片原始區域都在 0–100% 範圍內，且不使用每幀亂數。
4. 測試游標到圓角藥丸外 0px、14px、80px 的邊界距離，驗證範圍外一定回傳中性玻璃座標。
5. 實際 Overlay 檢查：播放結束時一次破碎、不閃爍、不移動藥丸；下一首開始時完全重組；滑鼠遠離藥丸時不再觸發液態跟隨。
6. 執行完整測試與 Vite build；不在本階段封裝 EXE，維持所有任務完成後才統一封裝。

## 已知限制

網易雲沒有可直接依賴的「自然播放結束」事件時，結尾只能根據已知歌曲時長、位置與播放／歌曲 ID 狀態組合判斷。沒有可靠時長的歌曲會略過破碎，這比在手動暫停或跳歌時誤觸發更符合預期。
